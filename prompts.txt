7. Ran the fixed version against the real video. Coarse scan completed
   and returned a "match" with confidence 100.0 — but the extracted text
   was "t\\", obviously not the target phrase. Flagged this as a false
   positive rather than accepting the output at face value.

--- What was produced from this prompt ---
- Root cause: rapidfuzz.fuzz.partial_ratio finds the best-matching
  substring of the SHORTER string's length inside the longer one. A tiny
  OCR fragment (here, normalizing down to a single character "t") can
  trivially "fully match" somewhere inside almost any target phrase,
  producing a false-positive 100 score.
- Fix: match_score() now returns 0 outright when the normalized candidate
  is shorter than MIN_LENGTH_RATIO (0.6) of the normalized target's
  length, before ever computing partial_ratio.
- Added a regression test (test_match_score_rejects_short_garbage_as_false_positive)
  that reproduces this exact case, so it can't silently come back.
- Also added: skip re-downloading the video if it already exists on disk
  (the source file is ~1GB — re-downloading on every parameter-tuning
  iteration wastes real time).
- This is a genuine example of finding a bug from real data (not a
  hypothetical), understanding *why* the library behaved that way, and
  fixing it at the root cause with a targeted guard + a test that pins the
  fix down — the kind of thing to be ready to explain and defend live.

8. Ran the fully fixed OCR pipeline against the real video end-to-end.

10. Asked to fix the word-level precision gap: the ASR path was reporting
    segment start time, not the exact word/phrase start time.

--- What was produced from this prompt ---
- Added word_timestamps=True to the faster-whisper transcription call
- Built a genuine coarse (segment) -> refine (word span) structure for
  the ASR path, mirroring the OCR path's design — find_best_word_span()
- Found a REAL BUG in this new code via the unit tests: reusing
  match_score() (partial_ratio) for word-span comparison let an
  incomplete window ("...rebels at", missing "stagnation") score
  competitively with the complete phrase, because partial_ratio doesn't
  penalize incompleteness. Fixed by adding full_match_score() (fuzz.ratio,
  whole-string comparison) as a deliberately separate function from
  match_score(), used specifically where candidate/target lengths are
  expected to be close — with a test that pins the distinction down
  (test_full_match_score_penalizes_incomplete_span)
- 19/19 tests passing after the fix
